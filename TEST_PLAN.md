# TEST_PLAN.md — план тестирования Cohorta

План ручного тестирования приложения. Охватывает счастливый путь, граничные
случаи и известные UX-баги. После каждого исправления проходите соответствующие
секции заново (regression).

## 1. Сид-скрипт (демо-данные)

Заполняет семестр **demo**: 3 курса, 10 лекций (текст, картинки, формулы MathLive),
2 набора карточек (9 карт).

```powershell
# из корня репозитория
npm run seed
# или из apps/web
npm run seed
```

Требования:
- PocketBase запущен на http://127.0.0.1:8090 (переменная окружения `PB_URL` переопределяет адрес);
- коллекции `decks`/`cards` уже созданы миграциями (п. 4 выше).

Ожидаемый вывод:

```
[seed] Semester "demo" created (...).
[seed] Course "Математический анализ" created (/math-analysis).
...
[seed] Done. Open http://127.0.0.1:5173, switch the semester to «demo» and check the dashboard.
[seed] Seeded: 1 semester, 3 courses, 10 lectures, 9 cards.
```

Повторный запуск безопасен: скрипт прерывается, если семестр `demo` уже
существует («nothing to do»). Для перезапуска с нуля удалите записи семестра
`demo` в админке (курсы/лекции каскадно удалятся, карточки — нет, удалите их
вручную) и запустите заново.

## 2. Счастливый путь (Happy path)

### 2.1 Авторизация
1. Открыть http://127.0.0.1:5173/logout (или очистить localStorage) → редирект на `/login`.
2. Ввести верный email/пароль → попадаешь на Рабочий стол, в шапке — имя и аватар.
3. Выйти через профиль в шапке → редирект на `/login`.

### 2.2 Создание лекции
1. На дашборде семестра нажать «+ Новая запись».
2. Ввести заголовок и конспект (пара абзацев, H2, чек-лист).
3. Сохранить → переход в просмотр, лекция видна, заголовок в шапке.

### 2.3 Редактирование и автосохранение
1. Открыть лекцию → «Редактировать».
2. Внести изменения, подождать 1,5–2 с → индикатор «Обновлено только что».
3. Нажать «Назад» до истечения debounce → лекция всё равно сохранена (flush при уходе).

### 2.4 Поиск
1. Кликнуть «Найти заметку» в шапке, ввести часть заголовка или слова из текста.
2. Из выпадающего списка выбрать лекцию → переход в просмотр.
3. Фокус на поиске: крошки плавно исчезают, при расфокусе возвращаются.

## 3. Граничные случаи (Edge cases)

| # | Сценарий | Ожидаемый результат |
|---|---|---|
| 1 | **Уход со страницы во время диктовки.** Включить микрофон, начать говорить, сразу перейти по ссылке | Страница уходит без краша; в аудио-блоке видна запись (необработанный interim — известная косметика, самозалечивается) |
| 2 | **Удаление курса с лекциями** (kebab → «Удалить» + подтверждение) | Всплывает ConfirmDialog; после подтверждения курс и его лекции исчезают из списка |
| 3 | **Отмена удаления** (кнопка «Отмена» в ConfirmDialog) | Ничего не удалено, курс на месте |
| 4 | **Вставка картинки 50 МБ** (drag&drop/вставка в редактор) | Появляется внятная ошибка, редактор не падает, текст не теряется |
| 5 | **Вставка картинки с кириллическим именем** | Файл загружается в `file`-поле, имя нормализовано, `[[file:...]]` резолвится |
| 6 | **Повторный запуск `npm run seed`** | Скрипт выводит «nothing to do», exit 0 |
| 7 | **Лекция без курса** (note, `/note/:lectureSlug`) | Открывается, в крошках нет курса: «Рабочий стол → запись» |
| 8 | **Старый семестр без slug** (привязка из «Без семестра») | Курс привязывается, слаги дозаполняются при редактировании |
| 9 | **Формула с ошибкой LaTeX** (вставить `\frac{a`) | Не валится просмотр/редактор; ошибка логируется в console.warn |
| 10 | **Неверный пароль на `/login`** | Показывается ошибка, остаёшься на `/login` |
| 11 | **Пустой ввод в редакторе, сохранение** | Лекция не создаётся с пустым заголовком/телом (валидация формы) |
| 12 | **Undo после вставки картинки** | Отмена не ломает редактор; файл на сервере может остаться (известное ограничение) |

## 7. Известные баги (вне текущей сессии)

1. **Interim-текст при уходе с диктовки** — может сохраниться с `data-speech-interim`
   (само-залечивается при дальнейшем редактировании).
2. **Не удаляются файлы картинок/аудио при удалении блока** — `deleteLectureFiles()`
   существует, но в автоделит не включена (не ломать undo).
3. **Белый экран после обновления при остановленном dev-сервере** — это
   закешированный HTML + SW-снапшот, не баг кода: запустить `npm run dev`, hard refresh.
4. **50 МБ картинка** — ожидается внятная ошибка, но время загрузки велико;
   лимит PB `MAX_BODY_SIZE`/`MAX_UPLOAD_SIZE` не превышен (см. граничный случай №4).
