# Cohorta — Design spec

Справочник для любого агента (Cline, Claude Code и т.д.), который пишет UI-код для Cohorta.
Правило: **новый экран собирается только из токенов и компонентов ниже**. Если чего-то не хватает — сначала расширяем этот документ, потом пишем код. Не изобретаем новый цвет, радиус или паттерн карточки на лету.

Ссылка: подключи этот файл в `.clinerules` (например, строкой `Follow /DESIGN.md for all UI work — do not deviate from its tokens or components.`), чтобы агент читал его в каждой сессии.

---

## 0. Первое правило: никакой «ИИ-дизайна по умолчанию»

Явный чёрный список того, что не используем, потому что это дефолты Tailwind/shadcn-стартеров и сразу считываются как шаблон:

- ❌ `indigo-500` / `#6366F1` и вообще дефолтная Tailwind-палитра как основной акцент
- ❌ Рандомные/радужные цвета на тегах, беджах, категориях без единой системы
- ❌ `rounded-full` на кнопках, инпутах, беджах — это даёт «мультяшный» вид
- ❌ Эмодзи как функциональные UI-иконки (в заголовках, кнопках, приветствиях). Эмодзи допустимы только как *контент пользователя* (иконка заметки/курса, которую выбирает сам юзер)
- ❌ Гейміфицированные виджеты без чёткой цели продукта (heatmap-заглушки, «стрики» ради стрика)
- ❌ Плоские цветные плашки-баннеры на карточках (сплошная заливка сверху карточки) — это генерик паттерн UI-кита
- ❌ Сплошной насыщенный highlight-фон на весь блок текста — маркер должен быть полупрозрачным
- ❌ Тени/градиенты «просто для красоты» вне определённых ниже паттернов
- ❌ Разные радиусы скругления в соседних компонентах одного уровня

Если агент не уверен, «дефолт это или осознанный выбор» — сверяется с токенами ниже, а не гадает.

## 1. Цвет

### 1.1 Бренд-градиент (единственный акцентный градиент бренда)
```
--brand-1: #5843F6;   /* тёмный конец */
--brand-2: #B5CBFA;   /* светлый конец */
--brand-gradient: linear-gradient(120deg, var(--brand-1), var(--brand-2));
```
Используется: логотип, hero-блок «Продолжить», primary-кнопка, аватар-плейсхолдер, активный пункт навигации (тонкая полоса-акцент).

### 1.2 Курируемая палитра курсов (6 градиентов, не больше)
Каждый курс получает один градиент из фиксированного набора — не свободный color-picker без ограничений (или color-picker, но с этими пресетами как основным путём). Все шесть подобраны на одной насыщенности/светлоте, чтобы не спорили друг с другом рядом:

| Имя | Градиент |
|---|---|
| violet (brand) | `#5843F6 → #B5CBFA` |
| coral | `#FF6B4A → #FFB199` |
| blue | `#2F80ED → #A5D8FF` |
| magenta | `#C239B3 → #F4A6E0` |
| green | `#0F9D77 → #A8E6C9` |
| amber | `#F5A623 → #FFE1A8` |

### 1.3 Нейтральные (UI-хром, текст, фон)
```
--ink:           #1C1C22;  /* основной текст */
--ink-2:         #5B5B66;  /* вторичный текст */
--ink-3:         #9494A0;  /* подписи, плейсхолдеры */
--bg:            #F7F7F9;  /* фон страницы */
--surface:       #FFFFFF;  /* карточки, панели */
--border:        #EAEAEF;  /* базовая линия */
--border-strong: #DFDFE6;  /* акцентная линия / hover */
```

### 1.4 Семантика (единственное место, где допустим «обычный» цвет)
```
--success: #0F9D77;   /* «Знаю» на карточках, успешные состояния */
--danger:  #E24B4A;   /* «Повторить», ошибки */
--warning: #F5A623;   /* предупреждения */
```
Не смешивать семантические цвета с цветами курсов — это два разных словаря.

### 1.5 Производные токены (добавлено при унификации App.css)
Без них в коде неизбежно появляются «почти такие же» значения — именно из них
набежало 78 разных hex до унификации. Ничего нового к палитре они не вводят:
это состояния и полупрозрачные варианты того, что уже объявлено выше.

```
/* бренд: hover и полупрозрачные варианты */
--brand-1-hover: #4A37E0;                  /* нажатие/hover primary-кнопки */
--brand-wash:    rgba(88,67,246,0.08);     /* wash-фон активного nav-item (§6) */
--brand-ring:    rgba(88,67,246,0.12);     /* свечение фокуса инпута (§6) */

/* семантика: текст на тонированном фоне и сами тона */
--success-ink:   #0B6B51;                  /* текст поверх --success-soft */
--success-soft:  rgba(15,157,119,0.10);
--danger-ink:    #B23A2A;                  /* текст поверх --danger-soft */
--danger-soft:   rgba(226,75,74,0.10);
--danger-border: rgba(226,75,74,0.28);
--warning-ink:   #8A5A00;                  /* текст поверх --warning-soft */
--warning-soft:  rgba(245,166,35,0.12);
--highlight:     rgba(245,166,35,0.25);    /* маркер в тексте заметки (§6) */

/* единственная тёмная поверхность продукта — блок кода */
--code-bg:  #2B2B33;
--code-ink: #F3F1FA;
```

Правило: `*-ink` — только для текста поверх соответствующего `*-soft`; на белом
фоне используется базовый `--success` / `--danger`.

### 1.6 Тени
Четыре ступени, больше не заводим. Тень обозначает высоту над поверхностью,
а не «красоту» (см. §0).

```
--shadow-sm:    0 1px 2px rgba(28,28,34,0.05);    /* границы-подсказки, чипы */
--shadow-md:    0 4px 14px rgba(28,28,34,0.07);   /* карточки, виджеты */
--shadow-lg:    0 16px 40px rgba(28,28,34,0.10);  /* попапы, модалки, дропдауны */
--shadow-brand: 0 10px 28px rgba(88,67,246,0.22); /* только primary-кнопка и hero */
```

### 1.7 Поверхности: без стекла
Фон страницы — плоский `--bg`, панели — непрозрачный `--surface` с `1px solid
var(--border)`. `backdrop-filter` допустим **только** на затемняющей подложке
модального окна (`rgba(27,27,27,0.35–0.45)`). Полупрозрачный белый поверх
фона — запрещён: до унификации в файле было 22 таких панели с 12 разными
значениями альфы, и именно поэтому соседние блоки не читались как одна система.

### 1.8 Legacy-алиасы `--c-*`
Старые токены (`--c-black`, `--c-lilac`, `--c-bg`, `--c-surface`, `--c-muted`)
оставлены как алиасы на канон, чтобы не переписывать 187 обращений разом.
**Новый код пишем только на токенах из §1.1–1.6.** Алиасы удаляем, когда
последнее обращение уйдёт из App.css.

## 2. Типографика

- UI/интерфейс (навигация, кнопки, лейблы, метаданные): **Inter**, вес 400/500/600. Не использовать 700 в UI-хроме — слишком тяжело.
- Заголовки заметок / крупные акценты на маркетинговых экранах (если появятся): один характерный display-шрифт с личностью, например **Fraunces** или **Instrument Serif**, использовать сдержанно — только h1/hero, не в теле.
- Тело конспекта (сам текст лекции): можно оставить Inter, либо для «читательского» ощущения — **Source Serif 4** / **Lora** — но выбрать один вариант и не менять на разных экранах.

Шкала размеров (px / вес):
```
h1  22 / 600
h2  17 / 600
h3  14 / 600
body 14 / 400
caption 12 / 500 (--ink-3)
```
Всегда sentence case. Никаких ВСЕ КАПС и Title Case вне имён собственных.

## 3. Форма, отступы, радиусы

```
--radius-sm: 8px;   /* инпуты, кнопки, беджи, строки навигации */
--radius-md: 12px;  /* внутренние карточки (белый слой поверх градиента) */
--radius-lg: 16px;  /* внешние градиентные карточки, hero-блок */
```
Правило: **чем крупнее контейнер — тем крупнее радиус**, но никогда не `9999px` / `rounded-full`, кроме круглых аватаров и точек-индикаторов.

Отступы — шкала 4/8/12/16/20/24/32px, без произвольных значений между.

---

## 4. Иконки

- Один набор на весь продукт: **Tabler icons** (outline), либо Lucide — не смешивать два набора.
- Единая толщина линии, единый размер в одном контексте (16px инлайн, 20px в навигации).
- Иконка = функция (поиск, курс, настройки). Эмодзи = пользовательский контент (человек сам выбрал 🎭 для конспекта по философии — это ок, это не UI-хром).

## 5. Паттерн карточки курса (сигнатурный элемент продукта)

Единственный способ показать цвет/принадлежность курсу — двухслойная карточка:

```
внешний слой:  border-radius: 16px; padding: 3px; background: var(--course-gradient);
внутренний слой: background: var(--surface); border-radius: 13px; padding: 14px;
```

Внутри — маленький бейдж-иконка (26×26, radius 8px, залит тем же градиентом) + заголовок курса + подпись последней лекции. Никаких дополнительных цветных плашек/баннеров сверху — цвет живёт только в градиентной рамке.

Этот же паттерн переиспользуется для: карточек курсов на дашборде, в «Все курсы», для точки-индикатора курса в сайдбаре (уменьшенная версия того же градиента), и на экране «Все экзамены» — тело карточки ниже названия курса заменяется прогресс-баром готовности вместо подписи последней лекции.

## 6. Компоненты

### Кнопки
- **Primary** — заливка `--brand-gradient`, белый текст. Максимум одна primary-кнопка на экран.
- **Secondary** — белый фон, `1px solid var(--border-strong)`, `--ink` текст. Основной тип кнопки по умолчанию.
- Радиус `--radius-sm`, паддинг `8px 14px`, иконка слева 15–16px.

### Беджи / теги
- Нейтральный фон (`--bg` или `--border`), текст `--ink-2`, плюс маленькая цветная точка (курс/категория) — не заливать весь бейдж цветом.

### Инпуты
- Фон `--bg`, без бордера в состоянии покоя, `--radius-sm`, фокус — 1px `--brand-1` + едва заметное свечение (`box-shadow: 0 0 0 3px rgba(88,67,246,0.12)`).

### Highlight в тексте заметки
- `background: rgba(245,166,35,0.25)` (или семантический жёлтый на 20–25% непрозрачности) вместо сплошной плашки. Текст поверх остаётся `--ink`.

### Чип статуса (карта билетов)

Плотная сетка одинаковых квадратных чипов, где один чип — одна единица работы
(билет), а цвет — её состояние. Нужен там, где элементов десятки и главный вопрос
экрана «где пробелы», а не «что это за элемент»: список из 80 строк на такой
вопрос не отвечает, сетка отвечает одним взглядом.

```
.exam-map-grid { display: grid; grid-template-columns: repeat(auto-fill, minmax(40px, 1fr));
                 gap: 8px; }
.exam-chip     { aspect-ratio: 1; border-radius: var(--radius-sm); font: 500 13px/1 Inter; }
```

| Состояние | Фон | Текст | Рамка |
|---|---|---|---|
| пусто | `--bg` | `--ink-3` | `1px --border` |
| черновик | `--warning-soft` | `--warning-ink` | `1px --warning` |
| готово | `--success-soft` | `--success-ink` | `1px --success` |

Цвет здесь **семантический** (§1.4), а не курсовой: чип показывает состояние работы,
не принадлежность предмету. Смешивать два словаря нельзя. Подпись при наведении —
через `::after { content: attr(data-label) }`, как в тепловой карте активности,
без тултип-библиотек.

Это навигация, а не геймификация (§0): чип кликабелен и ведёт к своей единице работы.

### Nav-item (сайдбар)
- Активный: лёгкий градиентный wash-фон (`rgba(88,67,246,0.08)` → `rgba(181,203,250,0.10)`) + тонкая градиентная полоса слева 3px. Текст — `--brand-1`.
- Обычный: `--ink-2`, hover — `--bg`.

## 7. Структура экранов (IA)

### Сайдбар
1. Логотип
1.5. **Переключатель Соло / Группа** — segmented-control из двух пилюль в общей
   капсуле сразу под логотипом (`.mode-toggle`). Активная пилюля залита `--surface`
   + `--shadow-sm`, неактивная — приглушённый `--ink-3` на `--bg`. В режиме «Соло»
   вся групповая механика в интерфейсе скрыта (пункт «Группа», кнопки «Доступ» /
   «Показать группе», «Участники» на экзамене). Переключение в «Группу» ведёт на
   экран «Моя группа», возврат в «Соло» с этого экрана — на дашборд
2. Переключатель семестра
3. Поиск
4. Глобальная навигация: Дашборд · Все заметки · Карточки · Экзамены · **Группа**.
   Пункт «Группа» виден только в режиме «Группа», ведёт на `/s/:sem/group`.
   «Экзамены» — сводка по всем курсам семестра (`/s/:sem/exams`), не сам экзамен
   конкретного курса: тот по-прежнему живёт в ветке курса (см. пункт 5), и этот
   пункт навигации его не дублирует, а собирает прогресс по всем курсам разом
5. Список курсов (точка-градиент + название + счётчик), разворачивается в заметки курса.
   Первой строкой раскрытого курса — «Экзамен» со счётчиком готовности (`34/80`), если
   экзамен заведён. Экзамен конкретного курса живёт только здесь, в его ветке — не
   отдельным пунктом навигации (это отличает его от сводки в пункте 4)
6. Профиль — внизу, второстепенный вес

Не дублировать одно и то же (заметка) одновременно в «Недавние» и в дереве курса — только один источник правды на список.

### Экран «Моя группа» (`/s/:sem/group`, только режим «Группа»)

Порядок блоков — против фрагментации потока (несколько групп на один реальный курс):
1. **«Есть код приглашения?»** — первым, самое заметное действие: поле + «Присоединиться».
2. **«Создать свою группу»** — вторым, приглушённым блоком за разделителем. Ввод названия
   ОБЯЗАТЕЛЬНО прогоняется через нечёткий поиск существующих групп (транслит + нормализация
   пробелов/дефисов). При совпадении сверху — карточки «Присоединиться к «…»» (первый план,
   `--brand-wash`), а создание превращается в неприметную ссылку «Всё равно создать новую».
   Создать «вслепую», не увидев результат поиска, нельзя.
3. **«Мои группы»** — карточка на группу: название, ссылка-приглашение с «Копировать»,
   ростер участников (бейджи «владелец» / «вы»). Счётчик написанных лекций у участника —
   этап B (нужно `lectures.owner`).

### Дашборд
Порядок блоков сверху вниз по частоте использования:
1. Приветствие — факт, без эмодзи и придуманной геймификации («8 новых заметок на этой неделе», не «ударный темп»)
2. Hero «Продолжить» — самое частое действие, всегда первым делом видно
3. Быстрые действия — три компактные кнопки, не одна доминирующая pill
4. Курсы семестра — сетка карточек по паттерну из раздела 5
5. Ближайший экзамен — показывается, только когда у экзамена задана будущая дата:
   предмет, «через N дней», «34 из 80 готовы». Всё три — факты из базы; если даты нет,
   блока нет (см. §0 про придуманную геймификацию)
6. «К повторению сегодня» (карточки на повторение) — служит ключевому сценарию продукта (сборка билетов к сессии), а не декоративный виджет
7. Последняя активность — вторична, компактный список

---

## 8. Голос / копирайтинг

- Активный залог, глагол в начале действия: «Новая заметка», не «Создание заметки».
- Без эмодзи в системных текстах и заголовках.
- Пустые состояния — приглашение к действию, не извинение: «Добавь первый курс», не «Пока здесь пусто».
- Ошибки — что случилось и что делать, без «Упс!» и извинений от первого лица.

## 9. Чек-лист перед тем как показать новый экран

- [ ] Использован ли только цвет из раздела 1 (никакого произвольного hex)?
- [ ] Радиусы соответствуют шкале из раздела 3?
- [ ] Нет ли рандомно раскрашенных беджей/тегов без системы?
- [ ] Нет ли эмодзи в UI-хроме (не в пользовательском контенте)?
- [ ] Использован ли существующий компонент вместо нового инлайн-стиля?
- [ ] Не появился ли декоративный виджет без чёткой пользы для сценария «конспект → карточки → билет к экзамену»?
