`## Outcome Roadmap` — cut/build/fix-лист. Остальные секции — лёгкие заглушки на будущее.

## Vision
Один инструмент, который держит всю подготовку студента к сессии: запись с занятия →
карточки для повторения → ответы на билеты → готовность к экзамену. Не заметочник и не
голый SRS, а связка между ними, чтобы «учиться регулярно» получалось само.

## MVP Definition

**Тип:** локальная PWA (Vite+React, PocketBase), один пользователь.

**MVP держит одну цепочку целиком:**
`завёл семестр → пишу конспекты → одним действием собрал карточки → каждый день вижу,
что повторить → к дате экзамена вижу готовность по билетам`.

**Осознанно НЕ входит в MVP:**
- Полноценный SRS с интервалами по оценке (SM-2). Вместо него — простое «давно не
  повторял» (решение фазы 9).
- Шеринг конспектов/колод, совместная подготовка (поле `is_public` — убрать до тех пор).
- Геймификация: стрики, heatmap, очки, бейджи, эмодзи (вырезается — см. Outcome Roadmap).
- Производительность/офлайн-полировка (фаза 8 отложена до выкатки на VPS).

## Opportunity Solution Tree Notes
Желаемый outcome: студент открывает продукт ≥ 3 раз в неделю в течение семестра (не
только перед сессией). Возможности: (1) стык «конспект → карточка» без трения;
(2) ежедневный повод открыть («на сегодня»); (3) видимая готовность к билетам.
Дерево целиком — в `nmt-diagnose`, когда появятся первые пользователи.

## Hook Model
- Trigger: внешний — «завтра/через неделю пара», расписание; внутренний — тревога «не успею».
- Action: открыть «на сегодня» → повторить порцию карточек.
- Variable reward: видимое сокращение «осталось до готовности по билетам».
- Investment: конспекты и карточки за семестр накапливаются → бросить дороже.
- **Слабое звено:** Action и Reward сейчас отсутствуют (нет «на сегодня», нет видимой
  готовности) → цикл не замыкается. B1+B2+B3 замыкают его.

## Discovery Cadence
Отложено (`continuous-discovery`): пользователей пока нет. Когда появятся первые студенты —
еженедельный созвон + `nmt-diagnose` на метриках воронки онбординга и частоты возвратов.
