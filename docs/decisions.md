# Решения по разработке

Одна строка на решение. Контекст: `spec-schedule-tasks-quiz.md`.

## 2026-10-16 — расписание / задачи / квиз / дизайн-основа

- Коллекция предметов — существующая `courses`; билеты — `exam_tickets`; связь билет→лекция — существующее поле `exam_tickets.sources` (новой миграции не нужно).
- Роуты `/schedule` и `/tasks` — глобальные, вне семестра. Задачи от семестра не зависят.
- Текущий семестр определяется флагом `semesters.is_current`, а не датами. Поля `start_date`/`end_date` в `semesters` — в бэклог (семестры у всех устроены по-разному).
- Якорь чётности недели хранится в `schedule_settings.odd_week_anchor` (по умолчанию понедельник текущей недели), не завязан на даты семестра.
- Расписание показывает слоты текущего семестра (`is_current`), иначе — последнего по `order`. `schedule_slots.semester` заполняется всегда.
- Новые дизайн-токены — в отдельном `src/styles/tokens.css`; стили новых компонентов — в `src/styles/components.css`. Существующие токены в `App.css` не трогаем; станут алиасами на шаге переноса (Релиз C).
- Шрифт только Inter; иерархия строится размером и весом, новые @font-face не добавляем.
- `zod` в проекте нет — валидация Gemini-ответа ручная, зависимость не добавляем.
- Тесты чистых функций — на Vitest (добавляем как devDependency); E2E остаётся на Playwright.
- Иконка пункта «Расписание» — `CalendarDays` (иконка `Calendar` занята кнопкой смены семестра), «Задачи» — `CheckSquare`.
- Мобильная нижняя панель вкладок создаётся с нуля (в проекте её нет).
- В редакторе используем только существующие блоки (SlashMenu, math/); блок «Определение», новые чипы и кнопки не добавляем сверх существующих.
- CF Function принимает уже извлечённый plain text; htmlToText на сервере не нужен (клиент стрипает HTML через DOMParser).
- Деплой Cloudflare Pages ручной — перед Релизом B останавливаемся и настраиваем `functions/` + переменные окружения вместе с владелицей.

**Визуальная проверка в браузере (сделана после первого отчёта о готовности):**
Подняты PocketBase + Vite dev, пройдено Playwright-скриптом: логин, `/schedule` (пустое и с добавленной парой), `/tasks` (пустое, быстрое добавление, чекбокс, фильтр по предмету), `/_design` — на 1280 и 360px. Найдены и исправлены 2 реальных бага:
1. **CSS**: `.app-main` (flex) и элементы `.ds-page__cols` (grid) не сжимались ниже min-content контента (стандартная ловушка `min-width: auto` у flex/grid-айтемов) — на 360px это распирало всю страницу горизонтальной прокруткой. Добавлен `min-width: 0` на `.app-main` и `.ds-page__cols > *`; вкладки `SegmentedControl` на мобильном дополнительно получили `overflow-x: auto` (spec 9.2).
2. **Даты из PocketBase**: поля типа `date` (`tasks.due/done_at`, `schedule_settings.odd_week_anchor`, `schedule_slots.date_from/to`, `lectures.lecture_date`) PocketBase отдаёt полным ISO-datetime («2026-10-25 00:00:00.000Z»), а не как записали («YYYY-MM-DD») — ломало `fromDateStr` (рендерило «NaN undefined NaN») и все строковые сравнения типа `due === today` (сегодняшние/просроченные задачи и пары без конспекта молча не находились). Добавлен `pbDateOnly()` в `localDate.ts`, применяется на границе сервисного слоя (`taskService.ts`, `scheduleService.ts`) для всех полей-дат сразу при чтении из PocketBase.

После фиксов: 0 ошибок консоли, 0 горизонтальной прокрутки на 1280/360, полный цикл (логин → добавить пару → добавить задачу → выполнить) проверен визуально по скриншотам.
