## 2026-10-16 — CF Pages Function для квиза развёрнута и проверена на проде

Деплой Cloudflare Pages уже был подключён к GitHub (автодеплой по пушу в `main`) — настройка root directory/build/переменных окружения сделана владелицей самостоятельно по чек-листу.

Серверная функция `functions/api/quiz/generate.ts` (spec 6.1) реализована, задеплоена и проверена **живым вызовом** на проде (реальный PocketBase на Amvera + реальный ключ Gemini в Cloudflare):
- 401/400/404/422 — все пути ошибок подтверждены curl-запросами к `https://cohorta.pages.dev/api/quiz/generate`.
- 502 — обнаружена и устранена проблема с моделью (ниже).
- 200 — финальный реальный вызов вернул корректно сформированный квиз (5 вопросов mcq с объяснениями и точными цитатами из текста лекции).

**Важная находка**: модель `gemini-2.5-flash` из черновика спеки недоступна новым аккаунтам Google («no longer available to new users», подтверждено ответом API). Через временный диагностический эндпоинт (`GET` того же пути, список моделей от Google, убран после диагностики) нашли рабочую замену — **`gemini-flash-lite-latest`** (алиас на актуальную Flash-Lite, более высокий бесплатный лимit, чем у Flash). `GEMINI_MODEL` в Cloudflare и `DEFAULT_MODEL`/`.dev.vars.example` в коде обновлены на неё.

Побочный эффект диагностики: создавалась и была удалена тестовая лекция на проде (`___TMP_QUIZ_TEST___`), реальных данных пользователя не затрагивало.

**Решение на будущее**: когда тестируем Gemini не с демо-данными, а ближе к реальным пользователям — останавливаемся и спрашиваем, прежде чем тратить их квоту.

## 2026-10-19 — волна B2 (лекции и поиск)

- **Статус лекции в списке «Все лекции» (4 бейджа):** «Слабо» (danger) — у лекции есть хоть одна слабая тема (accuracy темы < 0.6, как в панели понимания); иначе по общему percent: «Повторить» (warn) — percent < 75, «Выучено» (ok) — percent ≥ 75, «Не начато» (neutral) — квиза не было вовсе. Старая формула спеки 6.4 (2 порога, другие названия/цвета) заменяется этой — подтверждено владелицей на выбор из трёх вариантов.
- **Поиск одногруппников** идёт через существующий серверный ростер `/api/groups/:id/roster` (`pb_hooks/groups_access.pb.js`, A0.5), не напрямую через коллекцию `users` — её `viewRule` с A0.5 отдаёт только свой профиль, прямой запрос к чужим профилям для поиска по имени не сработает.
- **Поиск чужих лекций** — коллекция `lecture_previews`, фильтр только по `title`. Её `listRule` (ограничена участником группы) и серверный хук (строка появляется только если автор включил предпросмотр) уже достаточны — дополнительных проверок в клиентском коде не потребовалось. Проверено запросом на локальной копии со вторым тестовым аккаунтом (4 шага: без связи → 0, в группе без предпросмотра → 0, лекция привязана к группе но предпросмотр выключен → 0, предпросмотр включён → находится 1 запись по названию, `content` в записи нет).
- **Найдено, не чинил:** `lecture_previews.preview_text` хранит фрагмент текста лекции (до 400 символов), а не только заголовок — расходится со словарём («предпросмотр — название, не текст»). Это поведение из A0.5 (хук `lecture_previews.pb.js`), не из B2; мой поиск использует только `title`, но прямой запрос к коллекции всё равно отдаёт `preview_text` участнику группы. Решение, чинить ли, за владелицей.
- **Клик по найденной чужой лекции/одногруппнику в поиске — пока не ведёт никуда** (не ссылка): «Лекция закрыта / Запросить доступ» и профиль одногруппника — экраны волны C, которой ещё нет.
- **«Новая лекция» на «Все лекции»** ведёт на `/предметы` (там уже есть «+ Добавить лекцию» у каждого предмета) — в макете целевое действие кнопки не нарисовано, не стал придумывать отдельный флоу создания лекции без выбора предмета.

- **Онбординг 4 шага:** адрес профиля не спрашивается (поле `username` в базе и правка в настройках остаются), шага «Группа» нет. Все периоды создаются на «Готово», а не по шагам (раньше записи писались сразу).
- **Периоды по умолчанию** (`lib/studyPeriods.ts`): ступень → число лет (бакалавриат 4, специалитет 6, магистратура 2, «Другое» 4 — допущение), × периодов в году (семестры 2, триместры 3, четверти 4, своё 2). Даты образцовые только у семестров (01.09–31.01, 01.02–30.06); у остальных типов даты не подставляются (в макете их нет). Текущий период — тот, чьи даты включают сегодня (летом — ближайший следующий); у типов без дат — первый период нынешнего курса.
- **Даты периодов хранятся** в новых полях `semesters.date_from/date_to` (миграция 1790005000). В «Периодах учёбы» сохранение идёт по id записей (обновить/создать/удалить), а не «удалить всё и создать заново»: у периодов есть предметы и пары. Смена типа перемаркирует существующие периоды, число и даты не меняются. Автопереключения семестра по датам по-прежнему нет.
- **Правка в строке — один компонент** `ui/EditableRow` (текст, выбор, свои поля); выбор из списка на телефоне — шторка (`PickField`), выбор из шторки сохраняется сразу. Ошибка записи — подсказкой под полем, «Сохранить» остаётся.
- **Оглавление настроек** — кнопки с подсветкой по `IntersectionObserver`; после клика подсветка на 0,9 с не переписывается (прокрутка плавная).
- **Корзина (мягкое удаление):** `lectures.deleted_at`, `courses.deleted_at`; правила чтения и правки лекции/предмета (и квизов лекции) требуют `deleted_at = ""`, поэтому доступ одногруппников пропадает сразу, а `lecture_shares` не трогаются и доступ возвращается при восстановлении. Сама корзина идёт через серверные маршруты `/api/trash` (в обход правил, с проверкой владельца). Предмет уносит с собой свои лекции с тем же временем удаления; восстановление предмета возвращает именно их. Лекция, удалённая раньше отдельно, остаётся в корзине. Восстановление лекции при удалённом предмете возвращает и сам предмет (только его). Раз в сутки (03:00 сервера) стираются записи старше 30 дней. Клиентские `deleteLecture/deleteCourse` теперь кладут в корзину (5 секунд «Отменить» из прежнего интерфейса остаются). Превью лекции для группы из корзины не показывается.
- **Удаление аккаунта:** `POST /api/account/delete-request` (+14 дней, `scheduled_for`), `delete-cancel`; владелец группы с другими участниками получает 409, окно показывает предупреждение «Сначала передай владение» (передача — волна C). Раз в сутки (03:30 сервера) стираются аккаунты с истёкшим сроком: сначала данные, которые не удаляются каскадом, потом пользователь. Пока идут 14 дней, вместо приложения показывается экран «Аккаунт будет удалён …» с «Отменить удаление».
- **Выгрузка ZIP на клиенте:** собственный кодировщик ZIP без сжатия (`lib/zipStore.ts`, без нового пакета), папки по предметам (лекции в Markdown, `lib/htmlToMarkdown.ts`), таблицы CSV (задачи, расписание, билеты, колоды) с BOM; лекции без предмета — в папке «Черновики».
- **Служебные состояния, реальность и макет:** очереди раньше не было. Теперь: при ошибке сохранения лекции текст пишется в `localStorage` (по одному черновику на лекцию), автосохранение показывает «Сохранено на устройстве», сверху — полоса из макета (нет связи / не удалось сохранить / связь вернулась). Повтор — при событии `online`, возвращении во вкладку и раз в 15 секунд, пока приложение открыто; при открытии лекции более новый черновик подставляется в редактор и уходит сразу. «Не удалось сохранить» (красная) — когда сервер отказал (не сеть) или хранилище недоступно. Сессия: срок токена проверяется раз в 15 секунд и при возвращении во вкладку; окно «Сессия истекла» → «Войти» (черновик остаётся, после входа ProtectedRoute возвращает на прежнюю страницу). Очередь только для текста лекций.
- **404:** маршрут `*` и «не найдено» внутри лекции (удалена или нет доступа) показывают `NotFoundPage`; другие ошибки загрузки по-прежнему показывают прежний баннер ошибки.
- **Профиль на телефоне** (`/profile`): по `Screen-m-profile` (Соло) и `-m-profile-group` (Группа); строки «Уведомления», «Мой доступ», «Настройки группы» не показываются. На компьютере `/profile` переводит в `/settings`; профиль в сайдбаре — ссылка на `/settings`. На `/profile` верхней строки с поиском нет.
- **Не сделано из макета настроек:** «Начало недели» (нет поля в базе), правка отображаемого имени (в макете нет «Изменить»).
- **Токены `--space-5/-6/-7`:** в приложении остаются старыми (24/32/48), у дизайн-системы 20/24. В новом коде они не используются: 20 и 24 px считаются как `calc(var(--space-1) * 5)` и `calc(var(--space-2) * 3)`. Старые экраны (B2–B5) используют `--space-6` как 32 px; привести к дизайн-системе — отдельная уборка (волна D).
- **Радиус 20 px** вместо 24 у карточки онбординга (токена 24 нет), как у шторок B5.
